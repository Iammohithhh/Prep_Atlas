# Prep Atlas

A shared placement-practice website with separate DSA, AI/ML, aptitude and core-CS tracks. All executable code runs inside the visitor's browser; the server serves static assets only.

## Open it

Double-click `START_PREP.cmd`, or run:

```powershell
python serve.py
```

Open **http://127.0.0.1:8765**. Python is only required for the local web server. The site cannot be run by opening `index.html` directly, because workers and runtime assets require HTTP.

The editor supports Python 3.12, the standard library and NumPy. PyTorch, C++ and Java are not included. The first Run loads the local Python/NumPy assets. Stop cancels execution; runs are capped at 10 seconds and output at 64 KB.

## What is implemented

- Four question banks; search and company, topic, difficulty, progress, source and ML-role filters.
- Company-wide views across all tracks; topic coverage and represented-company counts.
- Problem/approach/notes views, MCQ and numeric answer checking.
- Python editor, standard input/output, errors, practice checks and cancellation.
- Attempted/solved/revisit status, autosaved code and notes, progress export/import.
- Light/dark/system themes, responsive phone layout and keyboard shortcuts.
- Original saved research reports, direct source links and limited-evidence labels.
- Explicit coverage reporting rather than treating extracted OCR as reviewed content.

Progress is stored independently in each browser. There are no accounts or cross-device sync. Export a backup before switching browsers or clearing site data. Import retains newer local records and ignores unknown question IDs.

## Content and provenance

`local` entries are archive transcriptions. `web` entries are paraphrased prompts from the saved reports; many are community submissions or snippets, not independently verified company questions. `practice` entries are original fully specified adaptations. Added practice interfaces and checks are labelled separately when attached to a local OA question.

Repeated full statements and explicitly equivalent patterns are merged; broad topics are not automatically merged. Meaningful variations remain separate. A passed practice suite is useful feedback, not a secure judge or proof over all inputs. Test cases are client-visible.

**The archive review is incomplete.** The Sources & coverage page lists the current reviewed-file and question counts. Original images, OCR text, candidate details and archive paths are never copied into `site/`. Extracted text can contain private details and stays under `build/ocr/`.

## Rebuild and resume

The public payload is reproducibly compiled from JSON, reviewed additions and research:

```powershell
python build/curate_local.py
python build/build_site_data.py
```

Build scripts require Python. Only OCR/PDF extraction and verification need extra packages:

```powershell
python -m pip install rapidocr_onnxruntime pillow numpy pymupdf python-docx playwright
python -m playwright install chromium
```

Resume local text extraction without publishing it:

```powershell
python build/extract_sources.py
```

The extractor checkpoints every file using atomic writes and validates caches before skipping them. Extraction is complete for all 1,320 current source files. Check saved coverage with `python build/extract_sources.py --audit`; use `--retry-errors` to retry error records. To extract a particular company, use `--company "Oracle"`. Per-file locks prevent overlapping work; verify that a lock's owner has stopped before removing a stale lock.

OCR does not guarantee accurate numbers, formulas, option lists or diagrams; inspect the source before adding a cleaned question. Private contact sheets can be generated with `python build/source_sheet.py Oracle --offset 0 --limit 20`. The original `TRANSCRIBE_SPEC.md` explains the question schema. `build/raw/curated_local.json` is generated by `curate_local.py` and its `reviewed_batch*.py` modules; edit those sources, not generated JSON. Explicit skips record unreadable or unresolved material and are not completed question transcriptions.

## Validation

```powershell
python build/practice.py
python build/verify_reviewed.py
python build/verify_batch12.py
python build/verify_batch13.py
python build/verify_batch15.py
python build/test_extraction_cache.py
python build/test_site.py
python build/test_site_edges.py
```

Reference solutions and selected reviewed algorithm explanations are compared with independent brute-force oracles. Browser checks require the local server on port 8765 and cover all 15 executable exercises, cold-load cancellation/restart, timeout recovery, progress-backup merging, filters, themes and settled mobile layout. QA screenshots remain private under `build/qa/`.

## Sharing and hosting

Publish **only the `site/` folder** to a static host. It includes the runtime assets and needs no API key or code-execution backend. Access control must be supplied by the chosen host if access is limited to batchmates. A static public deployment should not include the workspace root, archives, `build/`, `research/` or any private files.

For a trusted local network, explicitly bind the local server to your network interface:

```powershell
python serve.py --host 0.0.0.0 --port 8765
```

## Browser assets

Pinned third-party assets are local, so normal use requires no external CDNs. Source URLs are recorded in `site/vendor/sources.json`. The runtime is Pyodide 0.26.4 (Python 3.12) with NumPy 1.26.4; the editor is Ace. Markdown is rendered with Marked and sanitised with DOMPurify. KaTeX 0.16.22 renders formulas using local fonts.

- [Pyodide worker documentation](https://pyodide.org/en/stable/usage/webworker.html)
- [KaTeX browser API](https://katex.org/docs/api.html)
